# ADR 0005 — SEO y structured data

- **Estado:** aceptada
- **Fecha:** 2026-09-29

## Contexto

Cada calculadora necesitará URL limpia, title, description, canonical, H1, migas de pan, contenido explicativo, metodología, fuentes y structured data cuando corresponda. La marca y el dominio todavía no están definidos. No se quiere contenido masivo ni páginas artificiales por variante de keyword.

## Decisión

- **Un único constructor de metadatos** (`src/lib/seo/meta.ts` → `buildPageMeta`) produce title, description, canonical, robots y Open Graph a partir de los mismos datos. Falla si falta el título o la descripción. `SeoHead.astro` los emite. En las calculadoras, esos datos salen del registro mediante `calculatorPageProps` (ADR 0009).
- **Política de URL única:** sin barra final (`trailingSlash: 'never'` con `build.format: 'file'`, la combinación que recomienda Astro; en Vercel, `cleanUrls: true` y `trailingSlash: false`). El canonical elimina la query y el fragmento: los parámetros nunca crean URLs indexables. Las rutas van en minúsculas.
- **Indexación:** solo cuando `VERCEL_ENV === 'production'`, existe un dominio definitivo **y la identidad ya no es provisional** (`siteIdentity.isPlaceholder: false`, añadido el 2026-10-01). Además, el build falla si una página indexable contiene «PLACEHOLDER». Así, conectar el dominio antes de terminar la marca no indexa textos provisionales. En cualquier otro caso se emite `<meta name="robots" content="noindex, nofollow">`. Motivo: Vercel añade `X-Robots-Tag: noindex` a las previews, **excepto** a las que tienen un dominio propio (verificado el 29/09/2026 en su documentación).
- **`robots.txt` nunca bloquea el rastreo.** Google indica que "para que la regla noindex sea efectiva, la página no debe estar bloqueada por robots.txt" (developers.google.com/search/docs/crawling-indexing/block-indexing, consultado el 29/09/2026). El sitemap solo se anuncia cuando el sitio es indexable.
- **Sitemap:** `@astrojs/sitemap`, que excluye la 404, las páginas de prueba y las calculadoras que no están `published` en el registro (`unpublishedCalculatorPaths`). Las páginas de esas calculadoras en borrador se marcan además `noindex` (ADR 0008).
- **Estructura de página fija** (`CalculatorLayout`): migas → H1 → calculadora → contenido → metodología → fuentes → aviso → relacionadas.
- **Una URL por intención de búsqueda:** no se crean páginas por variante de keyword.

### Structured data (requisitos de Google verificados el 29/09/2026)

| Schema               | Decisión           | Motivo                                                                                                                                                                                                                  |
| -------------------- | ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **BreadcrumbList**   | Implementado       | Se genera a partir de las mismas migas que se muestran (`Breadcrumbs.astro`). Google exige `itemListElement` y, por elemento, `name`, `position` e `item`                                                               |
| **WebApplication**   | Preparado, sin uso | El rich result de software exige `offers.price` **y** `aggregateRating` o `review`. Sin valoraciones reales no es posible optar a él. El constructor no puede emitir ofertas, precios, valoraciones, reseñas ni autores |
| FAQPage              | No implementado    | Google indica que desde el 15/06/2026 ese rich result ya no se muestra                                                                                                                                                  |
| HowTo                | No implementado    | Descartado                                                                                                                                                                                                              |
| Organization / autor | No implementado    | Solo cuando exista un titular o autor real identificado                                                                                                                                                                 |

El JSON-LD se serializa escapando `<`, `>`, `&`, U+2028 y U+2029 (`serializeJsonLd`), de modo que un valor no puede cerrar la etiqueta `<script>`.

## Alternativas

- **Metadatos escritos a mano en cada página:** descartado; es fácil que diverjan del contenido.
- **Bloquear previews con `Disallow` en robots.txt:** descartado; impediría que se leyera el `noindex`.

## Motivo

Una sola fuente de verdad por página evita contradicciones entre el contenido visible, los metadatos y el structured data.

## Consecuencias

- **PLACEHOLDER:** la descripción de la portada es un marcador explícito, pendiente de definir la marca.
- Cuando exista el dominio, basta con definir `PUBLIC_SITE_URL` en Vercel. No hay que tocar código.
- **Decisión pendiente:** usar WebApplication en su forma mínima u omitirlo.
